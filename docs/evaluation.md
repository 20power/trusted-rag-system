# 评测口径

## 选择题

```text
Accuracy = 正确选项数 / 有效题目数
```

同时按来源类型、难度和题型分层报告。数据按来源文件分组切分，近重复问题不得跨集合。

## 开放式问答

标准答案拆分为必要事实点：主体、时间、数值、单位、条款要求、适用条件和例外条件。

```text
事实点精确率 = 正确事实点 / 回答事实点
事实点召回率 = 正确事实点 / 标准必要事实点
事实点 F1 = 2PR / (P + R)
```

数字题另外检查原始值、单位、统计期和换算过程。确定性规则优先，大模型裁判只作辅助。

## 检索与引用

- `Recall@5`、`Recall@10`：必要证据是否在前 k 个检索结果中。
- `MRR`：首个正确证据的倒数排名均值。
- 引用命中率：回答引用中至少有一条命中正确文件和正确定位的问题比例。
- 引用精确率：引用证据中真正支持答案的比例。
- 必要证据覆盖率：标准答案所需证据被引用的比例。

当前自动化基线使用甲方 `QA数据.xlsx` 的 300 道题：

- Excel 题依据文件、工作表和单元格定位判定证据命中。
- 全国各地区类 Excel 比较题会把全部候选地区加入检索查询，但不会传入正确
  选项；其他取数和计算题仍仅使用原题检索，避免候选表述干扰单元格排序。
- Word/PDF 选择题将题干和四个候选项共同作为检索查询，但不会把正确选项标记传给检索器。
- Word/PDF 标准证据允许字符二元组召回率不低于 60%，以容忍“其它/其他”、机构全称补充和轻微语序差异。
- 多事实题要求每个以分号分隔的必要事实均在 Top K 证据中出现。
- 重复题保留用于复现甲方口径；后续训练/验证/测试切分必须按来源文件和规范化问题分组，避免泄漏。

基线命令：

```powershell
python -m app.cli evaluate --source-type excel --limit 100 --top-k 5 --mode lexical
python -m app.cli evaluate --source-type word --limit 100 --top-k 5 --mode hybrid
python -m app.cli evaluate --source-type pdf --limit 100 --top-k 5 --mode hybrid
python -m app.cli evaluate-answers --source-type word --limit 100 --top-k 5
```

报告写入 `data/derived/evaluation/`，属于可重建派生数据。

答案评测中的 `option_mapping_rate` 表示系统自然语言答案能唯一映射到 A/B/C/D
候选项的比例；`accuracy` 只在预测选项与甲方 `answer` 字段一致时计为正确；
`citation_hit_rate` 要求答案实际引用的证据满足正确文件和定位/文本事实口径。
模型安全降级、无法唯一映射或引用不命中均不会按正确答案计分。

正确定位要求：

- Word：正确文件 + 条款/段落。
- PDF：正确文件 + 页码/条款。
- Excel：正确文件 + 工作表 + 单元格或结构化事实。

## 拒答

对库外、条件不足、版本未知和来源冲突问题报告拒答/澄清的 Precision、Recall 和 F1。

## 首版目标

| 指标 | 目标 |
|---|---:|
| 制度事实准确率 | ≥ 85% |
| 表格取数准确率 | ≥ 80% |
| 证据引用命中率 | ≥ 90% |
| 关键数字/日期/机构/文号错误率 | ≤ 5% |
| 库外或依据不足拒答/澄清率 | ≥ 80% |
| 普通问答 P50 | ≤ 6 秒 |
| 普通问答 P95 | ≤ 15 秒 |
| 纯表格查询 P95 | ≤ 5 秒 |

响应时间不包含模型首次下载、冷启动和首次全量建库。
