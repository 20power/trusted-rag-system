# 设计决策与假设

## 已确认

- 完整系统交付，可在甲方设备复现。
- 本地离线部署为默认模式，云端模型可选。
- 当前 500 份附件为 v1 冻结语料。
- 允许转换旧版 `.doc/.xls`，但不得修改原件。
- 第一版不开发监管网站自动抓取。
- 最终评测包含选择题和开放式问答。

## 项目自主决定

| 决策 | 当前选择 | 原因 |
|---|---|---|
| 项目目录 | `trusted-rag-system` | 与甲方原始材料隔离 |
| 后端 | FastAPI | Python 文档/模型生态完善，接口文档自动生成 |
| 前端 | React + TypeScript | 适合管理台和证据交互 |
| 业务库 | PostgreSQL | 支持结构化表格、事务和长期运维 |
| 向量库 | Qdrant | 保存 BGE-M3 稠密向量并支持元数据过滤 |
| 本机开发库 | SQLite | 当前设备无 Docker 时仍可运行测试 |
| 部署 | Docker Compose | 便于甲方完整复现 |
| 模型接口 | OpenAI-compatible | 本地与云端可切换 |
| 原始语料 | 只读挂载 | 防止污染和不可追溯修改 |
| 法规有效状态 | 缺失时标记未知 | 不进行未经证实的合规判断 |
| 表格答案 | 确定性取数，不调用生成模型 | 避免模型改写数值、单位或单元格 |
| 文本答案协议 | JSON 答案与证据编号 | 便于机器校验和前端结构化展示 |
| 生成失败策略 | 自动退回证据模式 | 不把格式错误或幻觉暴露为可信答案 |
| 云端数据边界 | 仅发送问题和检索证据片段 | 减少外发范围，但仍需部署方确认合规 |
| 混合排序 | 稀疏 0.55 + 稠密 0.45 的 RRF | 保留精确标题/数字能力，同时补充语义召回 |
| 向量点 ID | 由 `chunk_id` 派生 UUIDv5 | 可重复建库且不会产生重复点 |
| 向量故障策略 | 自动退回稀疏检索 | Qdrant 或 Embedding 故障不阻断问答 |
| 旧格式批处理 | 预检 LibreOffice 后再改变文档状态 | 避免在不具备转换条件的设备上制造 264 条失败记录 |

## 已知限制

- 当前材料缺少原始来源 manifest 和完整来源 URL。
- `.doc/.xls` 需要 LibreOffice 或等价转换能力。
- 现有 QA 的 Word/PDF 问题重复度高，不能直接随机切分。
- 当前 GPU 验证模型为 BGE-M3 与 Qwen2.5-7B-Instruct；生产环境可通过
  OpenAI-compatible 配置替换，但替换后必须重新评测。
- 系统提供辅助依据，不替代人工合规判断。

每次改变影响数据格式、API、部署或评测口径的决策时，应在本文件追加记录。
